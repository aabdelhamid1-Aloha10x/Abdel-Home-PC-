METRIC ENGINE (the core; server side):
- One SQL function per metric, signature metric_<key>(company uuid, driver uuid, period_start date, period_end date) returns numeric plus an explain jsonb of source rows. Implement now from existing data: miles_total, miles_loaded, loads_delivered, on_time_pickup_pct, on_time_delivery_pct, detention_minutes, paperwork_on_time_pct (documents uploaded within N hours of delivered_at), revenue, profit (using company cost settings), roll_call_on_time_pct, referral_hired. Metrics that need later data (safety_score, incident_free_days, clean_inspection_rate, pretrip_completed_pct, mpg, idle_pct, hos_violations, customer_rating) are registered in metric_definitions with available=false and shown disabled in the builder with the reason "needs <phase/integration>"; they light up automatically when their source exists. Custom metric = formula over two available metrics (safe expression parser, no eval).
- evaluate_program(program uuid, as_of date): for each eligible, enrolled driver compute value, tier, earned so far, projected (linear pace), write incentive_progress. Rules supported: threshold, tiers, ranking (top N within scope), improvement vs own previous period, streak (N consecutive periods), gates (extra metric conditions), caps (per driver, per program budget), proration for partial periods, exclusions (days on home time / out of service).
- close_period(program uuid, period): idempotent per (program, driver, period): writes incentive_awards (pending or approved by the program's approval rule), and when approved inserts the bonus settlement line into the driver's draft settlement for that cycle (create the draft if missing).
- Schedule: pg_cron nightly evaluate for all Active programs; period close at the configured time; manual "Recalculate now" button calls the same function.
- Unit tests (SQL or edge function tests): at least 15 cases: each rule type, proration, cap, ranking ties, idempotent close (run twice, one award), version change mid-period, pause then resume, end with each on-end rule (pay earned / forfeit / prorate), driver excluded, driver not eligible.

OFFICE UI (spec: match the mockups WebIncentives and WebIncentive):
- List: DataTable with tabs All/Active/Scheduled/Paused/Draft/Ended, KPIs, drawer, Templates menu (Safety streak, On-time delivery tiers, Fuel efficiency, Weekly miles tiers, Top-3 ranking, Referral bonus, Tenure milestone, Paperwork on time) that creates a Draft prefilled from the template, Recalculate now, row actions Activate / Pause / End with a confirm dialog that states the driver-side effect.
- Builder with cards Who, Measure, Rules, Reward, When, Approval: every control writes to the draft; eligibility shows a live "N drivers match" list; tier table editor with add/remove rows and validation (ascending thresholds, amounts >= 0); reward types flat, per mile, percent of revenue/profit, tier table, points; non-cash rewards create a task for the Owner.
- Preview as driver (renders the real driver card component with a sample driver), Cost estimate (runs evaluate in dry-run mode, shows projected payout per driver and total vs budget cap), Progress table with a "Why this amount" drawer showing the source loads/events from explain, Awards (Approve / Hold / Void / Add to settlement; approval permission required), History and versions (every rule change creates a version with effective_from; past periods keep the version they were earned under), per-driver override (exclude/enroll with reason).
- Activation: Activate runs a checklist (eligibility not empty, reward valid, budget cap set, preview opened) and then sets status Active (or Scheduled with starts_on). Pause stops accrual immediately; End asks the on-end rule. All status changes audited. Plan limit: Core one program with flat-reward + threshold only (UI and DB); Growth unlimited.

DRIVER UI (mobile, 390px, driver layout): /d/bonuses lists only programs where status = Active AND the driver is eligible and enrolled; opt-in programs show Join (creates enrollment) and Leave; progress bar to target, tier, earned so far, projected, days left, "What counts" expandable, history tab with past awards and "Added to settlement <date>" records. /d/bonuses/:id shows how it works in one plain sentence, progress, tier ladder, near-tier nudge, recent events that moved the number, and a Dispute button that opens the private Pay chat topic (Phase 3) or, until then, creates a message row. RLS: a driver can read only their own progress/awards; ranking programs expose only the driver's own rank (and top-3 initials only if the program flag allows). Deactivating a program hides it from the driver immediately (realtime), with an "ended" entry in history.
NOTIFICATIONS: new program available, close to next tier (within 10%), award earned, added to settlement; in-app now, push later.
